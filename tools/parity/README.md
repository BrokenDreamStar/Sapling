# Reference-vs-Sapling behaviour parity harness

Tools for comparing the behaviour of the **Carpet reference server**
(Minecraft 26.1 + Fabric + real Carpet 26.1) with the **Sapling server**
(this repo, Leaves 26.1.2 fork) while porting Carpet's fake-player (bot)
commands to Fabric Carpet's command surface.

Everything downloaded/generated by these scripts lives in
**<repo>/.carpet-ref/parity/**, which is git-excluded (.git/info/exclude).
`tools/parity/` itself only contains scripts and this README.
No tracked source file is modified and no Gradle build is invoked.

## Layout

~~~
tools/parity/
  setup-carpet.sh    idempotent downloader/preparer for the reference server
  run-carpet.sh      start/stop the Carpet reference server (background or foreground)
  run-sapling.sh     start/stop the Sapling server (jar argument or default build output)
  parity.py          pure-stdlib RCON client + command-sequence diff driver
  README.md          this file

.carpet-ref/parity/                      (git-excluded, generated)
  version_manifest_v2.json               cached Mojang manifest
  versions/26.1/26.1.json                cached version json
  versions/26.1/server.jar               vanilla Minecraft 26.1 server (60 MB)
  fabric-server-mc.26.1-loader.0.20.1-launcher.1.1.2.jar
  fabric-server-launch.jar               stable symlink to the launcher
  fabric-loader-26.1.json  fabric-installer.json
  carpet-versions-26.1.json              cached Modrinth metadata
  mods/fabric-carpet-26.1+v260402.jar    Carpet mod jar
  components.env                         resolved versions of everything above
  download-errors.log                    per-run download failures (empty when OK)
  carpet-server/                         reference server working dir
  sapling-server/                        Sapling server working dir
~~~

## Requirements

- Java 25 (Minecraft 26.1 requires major version 25; tested with 25.0.3)
- python3 (only the standard library is used)
- curl, and shasum/sha1sum (macOS ships shasum)
- Network access through the local proxy (see below)

## Proxy

The scripts default to the system proxy used on this machine:

~~~
HTTPS_PROXY=http://127.0.0.1:7897
HTTP_PROXY=http://127.0.0.1:7897
ALL_PROXY=http://127.0.0.1:7897
~~~

Existing environment variables win; set PARITY_NO_PROXY=1 in the environment to
skip the defaults entirely (e.g. for an offline run with a fully cached tree).
Direct access to piston-data/piston-meta, meta.fabricmc.net and api.modrinth.com
is expected to be unreliable/blocked on this host, so keep the proxy on for the
first setup and for the first Fabric server launch (the launcher downloads its
libraries then; later launches work offline).

## 1. Prepare the reference server

~~~
tools/parity/setup-carpet.sh
~~~

Idempotent: existing files that match their expected sha1 are skipped.
Resolved (current) versions are written to .carpet-ref/parity/components.env:

| component | version / file |
|---|---|
| Minecraft | 26.1 (server sha1 3872a7f0...7f46, 60,417,588 bytes) |
| Fabric loader | 0.20.1 (newest stable at setup time) |
| Fabric installer | 1.1.2 (newest stable at setup time) |
| Fabric launcher | fabric-server-mc.26.1-loader.0.20.1-launcher.1.1.2.jar |
| Carpet | 26.1 -> fabric-carpet-26.1+v260402.jar (sha1 f786a53c...0114) |

Override with MC_VERSION / FABRIC_LOADER / FABRIC_INSTALLER / PARITY_REF_DIR,
or force re-download with PARITY_FORCE=1. Download failures are retried at most
3 times, recorded in download-errors.log, and the script exits non-zero if a
required artifact is missing.

The generated carpet-server/ contains eula.txt, server.properties and mods/.
World settings (identical on both servers, flat preset, seed 12345):

~~~
server-port=25565        (Sapling: 25566)
online-mode=false
enable-rcon=true
rcon.port=25575          (Sapling: 25576)
rcon.password=parity
level-type=flat
level-seed=12345
spawn-protection=0
view-distance=10
simulation-distance=10
~~~

## 2. Build Sapling

The harness never builds the project. Build the server jar yourself first:

~~~
./gradlew :leaves-server:build
~~~

run-sapling.sh picks the runnable jar automatically: it prefers
leaves-server/build/libs/leaves-leavesclip-*.jar (the Paperclip equivalent),
then the newest non-sources/non-javadoc/non-bundler jar. You can also pass an
explicit jar path as the first argument or via SAPLING_JAR.

## 3. Start both servers

~~~
tools/parity/run-carpet.sh --wait-ready
tools/parity/run-sapling.sh --wait-ready
~~~

Both scripts:

- run java -Xmx2G by default (CARPET_MEM / SAPLING_MEM override)
- run in the background, write <server-dir>/latest.log and server.pid
- support --foreground, --wait-ready[=SECONDS], --reset-world, --stop, --help
- refuse to start twice; --stop sends SIGTERM (graceful Minecraft shutdown) and waits
- rewrite their generated server.properties on every start (the world is kept
  unless --reset-world is given)

ports: reference game 25565 / RCON 25575; Sapling game 25566 / RCON 25576;
RCON password "parity" on both.

Stop everything:

~~~
python3 tools/parity/parity.py --stop       # /stop over RCON on both, or:
tools/parity/run-carpet.sh --stop
tools/parity/run-sapling.sh --stop
~~~

## 4. Run parity checks

```
tools/parity/run-suite.sh                # all 18 cases, fresh world per case
tools/parity/run-suite.sh bot_physics    # selected cases only
python3 tools/parity/parity.py --case smoke        # 19 vanilla sanity commands
python3 tools/parity/parity.py --case bot_basic    # spawn/look/move/stop/kill
python3 tools/parity/parity.py --case bot_physics --tolerance 0.75
python3 tools/parity/parity.py --case bot_basic --only ref      # single-server test
python3 tools/parity/parity.py --commands my-case.txt --ticks 2 # your own sequence
python3 tools/parity/parity.py --list-cases
python3 tools/parity/check-status.py    # server-list ping player sample parity
python3 tools/parity/check-restart.py   # fake players are not persisted across restarts
python3 tools/parity/check-log.py       # join/leave/death console log messages
python3 tools/parity/check-data.py      # on-disk stats/advancements parity
python3 tools/parity/check-config.py    # allowSpawningOfflinePlayers=false branch (online mode)
python3 tools/parity/check-listing.py   # allowListingFakePlayers=true ping-sample branch
python3 tools/parity/check-permissions.py  # commandPlayer permission branch
python3 tools/parity/check-shadow.py    # /player shadow with a real protocol client
```

`run-suite.sh` stops both servers, resets their worlds, restarts them and runs
each case in isolation (state from a previous case cannot leak into the next).

Useful options:

| option | meaning |
|---|---|
| --case NAME | built-in case (default: smoke); see --list-cases |
| --commands FILE | run a command list instead of a built-in case |
| --ticks N | default wait after each command, in game ticks (commands file default 2); overrides built-in post-command waits |
| --only both/ref/sapling | which server(s) to drive (default both) |
| --ref-port / --sapling-port | RCON ports (defaults 25575 / 25576) |
| --password | RCON password (default parity) |
| --decimals N | decimal places kept when normalising (default 3) |
| --mask REGEX | mask extra per-server text before comparison (repeatable) |
| --raw | compare raw output without normalisation |
| --tolerance N | allow absolute numeric differences up to N (tick jitter; default 0 = exact) |
| --save-dir DIR | write transcript.txt and report.json |
| --stop | send /stop to the selected server(s) and exit |

Exit codes: 0 = no differences, 1 = differences found, 2 = setup/connection error.

### Commands file format

~~~
# comment (also //)
/gamerule advance_time false
wait 20              # wait 20 game ticks (1 second)
/player Steve spawn
/execute if entity Steve
~~~

A leading "/" is optional. Invalid/unknown commands are simply executed and
their error text is compared, so a missing command on one side shows up as a
normal diff (which is exactly what we want while porting bot commands).

### Output normalisation

RCON output is normalised before comparison: UUIDs become <uuid>, 32-hex ids
<hex32>, colour codes and [HH:MM:SS] timestamps are removed, and decimals are
rounded to --decimals places (coordinates like [0.5d, -60.0d, -60.0d] become
[0.5d, -60d, -60d]). Differences are printed as a unified diff (ref vs
sapling) per command, followed by a summary; --save-dir keeps the raw outputs.

### Determinism notes for MC 26.1

- **No spawn chunks for a player-less server.** 26.1 does not keep chunks
  loaded on its own, so /execute if block, /setblock and @e selectors fail with
  "That position is not loaded" until something loads a chunk. The built-in
  cases therefore /forceload add 0 0 first (and remove it afterwards).
- **Gamerule names are snake_case in 26.1**: advance_time (was
  doDaylightCycle), advance_weather, spawn_mobs, ... The cases use those names.
- **Bot timing**: most cases run the server normally and use sync barriers
  (/execute if entity Steve) after spawn/kill. Movement physics is measured
  with game-clock waits (/time query gametime, `--tolerance` absorbs the
  remaining one-tick command-phase jitter). Early cases can use /tick freeze +
  /tick step; note that on both servers fake players do not tick during frozen
  steps, so tick-frozen cases are only used for setup/teardown.
- **Zombies burn in daylight on both servers** (vanilla 26.1 behaviour), which
  silently adds damage over time to any summoned zombie. Cases that measure
  attack damage run at night (`/time set midnight`).
- **Flat world surface** of the generated preset is y=-60 (bedrock -64,
  dirt -63..-62, grass -61); bot cases assume that.
- Console-issued `/player <name> spawn` spawns fake players in **creative
  mode** (playerGameType 1) on both servers; the cases additionally spawn
  `in survival` when damage/health is being measured.

## Platform differences (not fake-player bugs)

These were found while comparing the Paper-based Sapling with Fabric/Carpet and
are normalised or worked around in the harness:

- **RCON long output**: Paper truncates long command feedback (~100 chars,
  ending in "..."), vanilla/Carpet sends it whole. Cases query NBT by short
  paths/inventory index instead of dumping large compounds.
- **Brigadier error context**: vanilla appends the "context" snippet to the
  error line; Paper sends it on a separate line. parity.py strips the context.
- **NBT compound key order**: Paper and vanilla serialize compound tags in
  different key order; parity.py sorts flat compound fields before diffing.
- **Chunk unload delay**: Paper keeps chunks loaded for
  `WorldConfiguration.delayChunkUnloadsBy` (default 10 s) after a player
  leaves; vanilla unloads immediately. bot_chunkload waits past the delay.
- **Paper client-load invulnerability**: Paper treats players whose client has
  not "loaded" as invulnerable for the first 60 ticks. Sapling overrides
  `hasClientLoaded()` in FakePacketListener to return true, matching Carpet.
- **Paper/Leaves spawn invulnerability**: vanilla 26.1 gives players 60 ticks
  of spawn invulnerability and Carpet fake players inherit it. Leaves disables
  it by config; Sapling's port re-enables it for FakePlayer only so fake
  players behave like Carpet's.

Total: ~632 RCON command comparisons, 0 differences.

On-disk player data (`check-data.py`): after a scenario that mines a block,
picks it up, receives an item and throws a snowball, both servers write the same
deterministic statistics sections (`mined`, `picked_up`, `used`, ...) and the
same advancement entries (recipe unlocks, adventuring_time); only the offline
UUID file name (vanilla vs CraftBukkit offline-uuid layout), time counters and
the top-level DataVersion are normalised.

Shadow (`check-shadow.py` + `mc_client.py`): a minimal protocol-775 client
(handshake -> login -> configuration -> play, compression/keep-alive aware)
logs in as a real player; `/player <name> shadow` must disconnect it with
`multiplayer.disconnect.duplicate_login` and leave a controllable fake player
with the same name/position/health, which can then be moved and killed.

Listing branch (`check-listing.py`): with `allowListingFakePlayers=true` the fake
player's real name appears in the SLP sample on both servers (`["ListBot"]`);
the default `false` behaviour (anonymous sample entry) is covered by
`check-status.py`.

Permission branch (`check-permissions.py`): `commandPlayer=false` hides the whole
`/player` command tree from the RCON console on both servers (identical
"Unknown or incomplete command"), while `commandPlayer=4` allows console use and
the fake player spawns asynchronously on both.

Config branch (`check-config.py`): `allowSpawningOfflinePlayers` only matters
in online mode, so both servers are started with `PARITY_ONLINE_MODE=true` and
the system proxy as JVM options. With the rule disabled both refuse
`/player <unknown> spawn` with the identical Carpet error message and spawn
nothing; with the rule enabled both accept it the same way.

Console log parity (`check-log.py`): the join/leave/death lines printed for a
fake player are the same on both servers (`joined the game`, `logged in with
entity id ...`, `died`, `lost connection: ...`, `left the game`); only the
entity id counter and Paper's dimension prefix in the login line differ, which
the check normalises.

Restart persistence (`check-restart.py`): after spawning a fake player and
restarting both servers, neither restores the fake (Carpet semantics: fake
players are not saved) — both report an empty player list.

Server-list ping parity (`check-status.py`): with a fake player online both
servers report `{"online": 1, "sample": ["Anonymous Player"]}` (Carpet's
`allowListingFakePlayers=false` hides the name behind the anonymous sample
entry while still counting the player); after the fake is killed both report an
empty sample. The script waits 6 s because both servers cache the ping response
for 5 s.

Notes on the config schema: `fakeplayer.command-player` accepts the carpet forms
`ops`, `true`/`false` and `0`..`4`; unquoted YAML booleans/numbers are normalised by
`CommandPlayerConfigValidator` so `command-player: false` behaves like carpet
instead of silently falling back to the default.

## Troubleshooting

- "cannot connect to 127.0.0.1:25575/25576": the server is not running or still
  starting. Start it with --wait-ready and check <server-dir>/latest.log.
- "RCON login failed": rcon.password mismatch; the generated properties use
  "parity" on both sides.
- Reference server exits on first launch: check that the proxy is running and
  see .carpet-ref/parity/carpet-server/latest.log; the Fabric launcher needs
  the network once to download loader libraries.
- Java < 25: set JAVA=/path/to/java25 (run scripts warn and continue).
- Fresh world state: add --reset-world to a run script (deletes only
  .carpet-ref/parity/<server>/world, verified to stay inside .carpet-ref).
